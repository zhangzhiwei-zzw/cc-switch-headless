# Web 排错指南

浏览器操作的是服务器进程所在用户的文件。先确认部署方式、实际运行用户和配置目录，再进行恢复操作。功能是否支持请先查 [应用支持表](web-app-support.md)。

## 先收集最小诊断

在服务器本机执行以下只读命令，按部署方式选择日志：

```bash
curl -i http://127.0.0.1:15800/healthz
curl -i http://127.0.0.1:15800/readyz
systemctl --user status cc-switch-server
journalctl --user -u cc-switch-server -n 80 --no-pager
# Docker 部署使用：docker compose logs --tail=80 cc-switch-web
```

端口不是 15800 时替换它。`/healthz` 为 200 只证明进程可响应；`/readyz` 为 503 表示数据库未就绪。二者仍会检查 Host/Origin。

登录后可在“关于”查看版本、构建提交和运行信息；`GET /api/env` 也返回诊断信息，但需要认证。日志可能包含首次登录链接、私人路径和业务内容，提交 Issue 前删除令牌、API Key 和会话正文。

出错提示中的 `[request UUID]`、响应头 `X-Request-Id` 和 API 错误的 `requestId` 可用于日志关联。搜索同一编号以查看命令、错误 code 与耗时；不需要提供完整请求体。`E_INTERNAL` 不向客户端暴露后台异常细节。

## 常见现象

| 现象 | 先检查 | 对应说明 |
| --- | --- | --- |
| 连接被拒绝、502 | 服务是否运行、反代上游地址和网络位置 | [连接与反代](#连接与反代) |
| 401、反复要求登录 | 令牌、Cookie、轮换、HTTP/HTTPS | [登录与令牌](#登录与令牌) |
| 400 Host 或 403 Origin | 精确白名单与透传 Host | [Host 与 Origin](#host-与-origin) |
| 页面打开但事件不更新 | SSE 缓冲、超时、令牌轮换 | [事件流与超时](#事件流与超时) |
| 看不到原有供应商/会话 | 服务运行用户、挂载目录、CLI 原生数据 | [配置和容器目录](#配置和容器目录) |
| `E_NOT_IMPLEMENTED` | 功能支持范围、旧前端缓存 | [接口与版本不匹配](#接口与版本不匹配) |
| `E_CONTRACT` | 前后端版本、返回结构 | [接口与版本不匹配](#接口与版本不匹配) |
| `/readyz` 为 503 或 `E_INIT` | 数据库版本与初始化日志 | [数据库与恢复](#数据库与恢复) |
| 安装/上传失败 | 架构、校验和、权限、容量与反代限制 | [安装与文件传输](#安装与文件传输) |

## 连接与反代

默认服务只监听 `127.0.0.1:15800`。远程浏览器要通过 SSH 隧道或 HTTPS 反代：

```bash
ssh -L 15800:127.0.0.1:15800 user@server
```

随后在本地浏览器访问 `http://127.0.0.1:15800/`。本地端口被占用可改成 `-L 15801:127.0.0.1:15800`，浏览器相应使用 15801。

502 通常需要核对反代能否连接上游。反代在容器内时，`127.0.0.1` 指反代容器本身；使用正确的容器服务名/网络。不要通过关闭令牌或把端口直接暴露公网来解决连通问题。完整 Nginx/Caddy 配置见 [HTTPS 部署](web-mode-zh.md)。

当前前端与 API 使用根路径 `/`、`/api/...`。请使用独立域名或根路径部署；`/cc-switch/` 等子路径不是当前保证支持的部署方式。

## 登录与令牌

- 首次启动从真实配置目录中的 `web-token` 或服务器日志获取令牌，在登录页输入。
- 令牌轮换会使旧 Cookie 和 SSE 失效，重新登录是正常行为。多实例不要复用显式 `--cookie-name`，默认实例名称会隔离。
- `--hsts` 会使 Cookie 带 `Secure` 标记，用于 HTTPS 反代；给本地明文 HTTP 错加该选项时，浏览器可能无法发送会话 Cookie。
- 切换域名、端口或配置目录后，确认访问的是同一个实例。浏览器访问 `localhost` 与 `127.0.0.1` 时 Cookie 不共享。
- 手动令牌必须至少 16 字符，仅使用 `A-Z a-z 0-9 - _ . ~`；旧令牌不合规会在启动时报错。优先使用自动生成值。
- 命令行可用 `Authorization: Bearer ...` 认证，避免依赖浏览器 Cookie。不要公开完整登录 URL，也不要在反代访问日志中记录查询参数。

不建议删除 `web-token` 作为第一步：先核实目录和外部环境变量。通过 `--token` 或 `CC_SWITCH_WEB_TOKEN` 提供值时，该来源重启后仍会生效。

## Host 与 Origin

默认仅允许回环主机。域名访问应在服务器启动参数设置 `--allow-host cc-switch.example.com`，或用 `CC_SWITCH_ALLOW_HOSTS` 配置逗号分隔的精确主机列表。

- 反代应保留原始 `Host`，Nginx 示例为 `proxy_set_header Host $host`。
- 白名单不接受通配符；使用非默认端口时对照部署说明核对主机与端口。
- 浏览器 POST 携带的 `Origin` 也会被检查。不要删除 Origin 或使用任意来源放行来掩盖部署错误。
- 400/403 也可能来自反代。比较服务器本机与公网请求，查看响应正文和两端日志再定位。

## 事件流与超时

`/api/events` 使用 SSE。反代应关闭缓冲并允许长连接，例如 Nginx 的 `proxy_buffering off` 和 `proxy_read_timeout 3600s`。浏览器网络面板中 SSE 长期处于 pending 是正常现象，不代表请求卡死。

令牌轮换、退出服务或网络中断会关闭事件流。先确认认证和连接，再重新打开页面；不要把 SSE 的 401 当作业务命令失败。

Web 普通命令等待 60 秒，长导入/安装/同步等为 5 分钟，会话流为 2 分钟。请求超时后先查操作结果和日志：后端任务可能仍在执行，重复点击导入、恢复、安装可能造成重复操作。大会话当前仍需在后端完整解析；分块传输不等于无限大小或恒定内存。

HTTP 429 或 `E_BUSY` 表示两个会话读取名额已被占用，稍后重试；客户端断开不会强行停止已经运行的解析任务。`E_SESSION_LIMIT` 表示文件源预检超过 64 MiB、序列化结果超过 32 MiB 或单条消息超过 2 MiB，请改用原生 CLI 查看。SQLite 不以整个数据库大小判断单个会话是否可读，仍受输出和并发限制。

## 配置和容器目录

- CC Switch 数据目录按 `CC_SWITCH_CONFIG_DIR`、已有目录覆盖配置、默认 `~/.cc-switch` 的顺序解析。以“关于”或已认证 `/api/env` 的实际路径为准。
- CC Switch 数据目录不是所有 CLI 的根目录。Claude、Codex、Kimi 等仍有各自的目录和环境变量，服务用户必须能读取它们。
- systemd 用户服务通常不会继承交互 shell 后来设置的环境变量。使用 `systemctl --user edit cc-switch-server` 配置 `[Service] Environment=...`，然后执行 daemon-reload 和 restart。
- 默认 Compose 将数据卷挂到 `/data`，CLI 路径需按 `docker-compose.yml` 示例另行挂载；主机上存在文件不代表容器内能看到。
- 修改权限前先核对容器运行用户、主机文件属主与可写目录。不要对包含密钥的目录递归设置 777。
- Kimi 的 `KIMI_CODE_HOME`、Pi 的项目相对会话路径等特殊情况见 [应用支持表](web-app-support.md) 与对应接入文档。

## 接口与版本不匹配

`E_NOT_IMPLEMENTED` 表示命令未在 HTTP 分发表注册；`E_CONTRACT` 表示已覆盖的请求/响应结构不符合约定。

1. 对照运行时 `/api/capabilities` 和 [应用支持表](web-app-support.md)，确认功能已接入。
2. 使用强制刷新或私密窗口排除浏览器缓存；检查反代是否缓存了旧首页。
3. 使用 `--dist` 时核对该目录是否来自同一份源码。它优先于二进制内置资源，升级二进制不会自动更新这个目录。
4. 新前端与旧后端混用时，先部署对应构建版本，再排查具体命令。不要用能力表里不存在的功能强行调用。
5. 仍可复现时报告命令名、错误阶段和构建提交，参照 [接口契约](web-api-contract.md)，不要附带请求中的凭据。

新构建会生成 `.gz` 静态资源；自定义 `--dist` 没有同名压缩文件或压缩文件比原文件旧时，会返回原始内容。不要混合不同构建的文件；`gzip;q=0` 会禁用 gzip。缺失的 JS/CSS 资源现在返回 404，SPA 回退仅用于不带文件扩展名的页面路径。

浏览器可能显示 CSP Report-Only 诊断，它不会像强制策略一样阻止相关资源。目前仅强制 object/base/form/frame 限制，完整资源策略尚处于观察阶段；未配置中央 CSP 上报接口。报告兼容性问题时注明控制台的指令和被拒来源，并移除任何带令牌的 URL。

## 数据库与恢复

`healthz=200`、`readyz=503` 时进程可以存活，但数据库未就绪；命令可能返回 `E_INIT`。先查看启动日志和初始化错误，区分权限不足、文件损坏与数据库版本过新。

数据库版本高于当前二进制支持版本时，优先换回支持该数据库的较新二进制。**仅替换旧二进制不等于数据库回滚**；不要手改 SQLite `user_version` 或删除数据库来绕过检查。

正常运行时可从 Web 的备份功能创建/导出备份。初始化失败时仅恢复界面和诊断可用，不应假定备份恢复命令仍能执行。需要文件级恢复时：

1. 停止服务，保存当前 CC Switch 数据目录的完整私有副本，包括可能存在的 SQLite WAL/SHM 文件；同时备份受影响的 CLI 配置。
2. 选用与备份兼容的二进制及可信备份，按 [升级与回滚说明](web-mode-zh.md) 恢复。
3. 重新启动，检查就绪状态、供应商配置和路由。不要把旧版本数据库与新版本遗留的 WAL 文件随意拼在一起。

备份、导出及诊断可能包含 API Key 和访问令牌，不上传到公开 Issue，也不放在公共下载目录。

## 安装与文件传输

- `--service` 属于安装脚本，不属于服务端二进制。用 `bash scripts/install-server.sh --service` 安装用户服务。
- 架构不匹配或 GLIBC 报错时核对下载资产与系统版本；Linux 产物要求 glibc ≥ 2.31，不适用于直接在 Alpine/musl 中执行。
- SHA256 不匹配时停止安装，重新获取同一版本的二进制和校验文件；不要跳过校验。
- 上传失败先核对反代请求体限制与服务器权限。HTTP 413 表示请求体过大；HTTP 507 可由传输配额或写盘失败引起。
- 上传/导出临时文件 24 小时过期，总容量上限 512 MiB；过期链接需要重新导出。临时传输文件不能代替长期备份。

## 提交问题时

提供系统/架构、部署方式、版本与构建提交、预期与实际结果、最小复现、脱敏日志，并说明本机直连是否可复现。功能建议与普通问题使用本仓库 Issue；漏洞使用 [私密报告入口](../SECURITY.md)。
